# kMessage 管理后台页面功能描述

本文档基于当前 Vue 3 管理端源码整理，用于重新生成 Figma 设计稿。

## 产品定位

kMessage 是面向内部服务的统一消息平台。管理后台用于创建业务应用、发放调用凭据、配置消息渠道、授权应用可用渠道，并在控制台内完成渠道测试发送。首期支持 Telegram 和飞书文本消息，邮箱类型仅作为扩展占位，不能启用或发送。

## 全局应用状态

- 启动时先检查浏览器 Session，检查期间展示全屏加载态“正在检查登录状态”。
- 未登录时进入登录页。
- 已登录时进入管理控制台并拉取应用列表、渠道列表和渠道类型。
- API 统一返回 `success/data/message` 结构；401 会让前端回到未登录状态。
- 成功操作使用成功 toast；失败操作使用错误 toast。

## 页面一：登录页

### 入口条件

用户未通过 `/api/admin/session` 校验时展示。

### 页面目标

让管理员用后台用户名和密码建立浏览器 Session，进入 kMessage 管理控制台。

### 主要内容

- 居中登录卡片。
- 品牌区：`K` 品牌标识、`kMessage` 标题、说明文案“统一消息平台管理后台”。
- 表单字段：用户名、密码。
- 主操作：登录。

### 交互和状态

- 用户名或密码为空时，登录按钮禁用。
- 提交时按钮进入 loading 状态。
- 登录成功后清空密码、进入管理控制台并加载基础数据。
- 登录失败时展示错误 toast。

### 设计重点

- 单任务、低干扰。
- 背景为浅色工作台底色，保留柔和高亮，但不抢占表单焦点。
- 卡片宽度约 440px，适配移动端。

## 页面二：管理控制台

### 入口条件

用户已登录且 Session 有效。

### 页面目标

提供统一的消息平台运营工作台，让管理员可以管理应用凭据、渠道实例和应用到渠道的授权关系。

### 布局结构

- 顶部导航栏固定在页面顶部。
- 主工作区可纵向滚动，最大内容宽度约 1200px。
- 顶部摘要区展示页面目标与核心指标。
- 内容区使用两列面板：应用凭据、渠道实例；窄屏降为单列。

### 顶部导航栏

功能：

- 展示品牌：`K` 标识、`kMessage`、副标题“消息平台管理后台”。
- 刷新按钮：重新拉取应用、渠道和渠道类型数据。
- 退出按钮：销毁 Session 并回到登录页。

状态：

- 刷新时按钮展示 loading。

### 摘要区

功能：

- 文案：`Console`、`管理消息发送身份与渠道`、`创建业务应用、配置消息渠道，并控制应用可使用的渠道。`
- 指标卡片：业务应用数量、渠道实例数量。

设计重点：

- 这是工作台标题区，不做营销型大首屏。
- 指标要便于快速扫描。

### 临时密钥提示

出现条件：

- 创建应用或轮换 Secret 后，后端返回新的 `appKey` 和一次性 `appSecret`。

功能：

- 警示标题“请立即保存新凭据”。
- 说明 AppSecret 仅本次展示，刷新后不再显示。
- 展示 `appKey` 和 `appSecret`，并提供复制按钮。

设计重点：

- 使用 warning 语义。
- 明确一次性、不可恢复的风险。

## 模块：应用凭据

### 模块目标

管理业务应用身份。每个业务应用拥有独立的 `appKey` 与 `appSecret`，用于业务侧调用消息发送接口。

### 主要内容

- 新建应用表单：应用名称输入框、创建应用按钮。
- 应用表格：
  - 名称。
  - appKey，使用脱敏展示并支持复制。
  - 操作：绑定渠道、轮换 Secret、删除。
- 空状态：暂无应用，引导创建第一个业务应用。

### 交互和状态

- 应用名称为空时，创建按钮禁用。
- 创建成功后清空表单、刷新数据、展示临时密钥提示。
- 轮换 Secret 后刷新数据，并展示新的临时密钥提示。
- 删除应用前弹出确认，提示凭据会立即失效。

### 绑定渠道弹窗

入口：

- 应用表格行操作“绑定渠道”。

功能：

- 标题展示当前应用名称。
- 拉取该应用已授权渠道。
- 多选渠道实例，选项格式为“渠道名称（渠道类型）”。
- 保存时自动计算新增授权和撤销授权，分别调用授权或撤销接口。

状态：

- 打开时展示保存中或加载态。
- 取消关闭不保存。

## 模块：渠道实例

### 模块目标

配置可发送消息的渠道实例。渠道凭据通过环境变量引用，控制台不展示明文。

### 主要内容

- 新建渠道表单：
  - 渠道名称。
  - 渠道类型。
  - 凭据引用，如 `env:SECRET_NAME`。
  - 创建渠道按钮。
- 渠道接入指南：
  - 根据当前选择的渠道类型展示名称、描述、配置步骤。
- 渠道表格：
  - 名称。
  - 类型徽标。
  - 状态徽标：启用或停用。
  - 凭据，长文本折叠展示。
  - 操作：发消息、编辑、删除。
- 空状态：暂无渠道，引导创建渠道实例。

### 交互和状态

- 只有已实现的渠道类型可选择；未开放类型禁用。
- 渠道名称、类型、凭据引用都存在时才能创建。
- 创建渠道默认启用，默认高级配置为 `{}`。
- 仅启用状态的渠道展示“发消息”操作。
- 删除渠道前先拉取删除影响预览，再确认删除。

### 发送消息弹窗

入口：

- 已启用渠道行操作“发消息”。

功能：

- 标题展示当前渠道名称。
- 展示并可复制 `channelInstanceId`。
- 打开时拉取渠道联系人。
- 目标选择：
  - 有联系人时可从联系人下拉选择。
  - 联系人为空或拉取失败时，允许手动输入 target。
- 消息内容输入，默认“测试消息”。
- 提交后展示发送成功或发送失败结果。

状态：

- 联系人拉取中、拉取失败、空联系人、有联系人四种提示。
- 目标和消息内容都存在时才能发送。
- 发送中按钮展示“发送中...”。

### 编辑渠道弹窗

入口：

- 渠道表格行操作“编辑”。

功能：

- 修改渠道名称。
- 切换启用状态。
- 可选更新凭据引用，留空表示不修改。
- 编辑高级配置 `configJson`。

状态：

- 渠道名称为空时保存按钮禁用。
- 保存后关闭弹窗并刷新数据。

## 历史/备用模块：应用渠道授权

源码中存在 `GrantPanel` 组件，但当前 `AdminConsolePage` 未挂载该模块。它提供基于应用和渠道两个下拉框的授权/撤销能力。当前页面实际使用“应用凭据”表格内的“绑定渠道”弹窗承载授权管理。

设计稿中不应把该模块作为当前主页面区域新增，除非后续产品决定恢复独立授权面板。

## 关键数据来源

- `GET /api/admin/session`：检查登录态。
- `POST /api/admin/session/login`：登录。
- `POST /api/admin/session/logout`：退出。
- `GET /api/admin/applications`：应用列表。
- `POST /api/admin/applications`：创建应用。
- `POST /api/admin/applications/{id}/rotate`：轮换 Secret。
- `DELETE /api/admin/applications/{id}`：删除应用。
- `GET /api/admin/channels`：渠道列表。
- `GET /api/admin/channel-types`：渠道类型。
- `POST /api/admin/channels`：创建渠道。
- `PUT /api/admin/channels/{id}`：更新渠道。
- `GET /api/admin/channels/{id}/contacts`：拉取并同步联系人。
- `POST /api/admin/channels/{id}/send-message`：测试发送消息。
- `GET /api/admin/channels/{id}/delete-preview`：删除前影响预览。
- `DELETE /api/admin/channels/{id}`：删除渠道。
- `GET /api/admin/applications/{id}/channels`：查询应用已授权渠道。
- `PUT /api/admin/applications/{applicationId}/channels/{channelId}`：授权渠道。
- `DELETE /api/admin/applications/{applicationId}/channels/{channelId}`：撤销授权。

## 设计系统线索

- 前端使用 `@kk-2004/ui-components` 作为主要 UI 组件库。
- Select、Table、Switch 使用 Element Plus。
- 主色：`#315EFB`。
- 文本主色：`#182033`。
- 页面底色：`#F5F7FB`。
- 边框色：`#E4E7EC`。
- 成功色：`#16A34A`。
- 警告色：`#F59E0B`。
- 危险色：`#D92D20`。
- 字体：Inter、PingFang SC、Microsoft YaHei、system-ui。
- 控制台是面向重复操作的管理工具，应保持高信息密度、克制色彩、清晰表格和明确操作区。
